## 一、概述

挂起的本质是把系统从"正常工作"收缩到"只剩RAM自刷新或完全断电"，收缩过程
由多个回调机制分段完成，硬件模块根据自身属性挂到其中一种或几种机制上：

```
阶段1  多CPU在线/可睡眠/中断可用    DPM设备回调 + 进程冻结
阶段2  非启动CPU逐个下线            cpuhp状态机
阶段3  单CPU/关中断/不可睡眠        syscore + cpu_pm通知链
阶段4  内核交出CPU                  platform enter + cpu_suspend
```

判定一个硬件模块挂哪种机制，回答三个问题：

1. 它是谁的资源：属于设备还是CPU还是整个系统？
2. 掉电域划分：挂起时它所在的电源域掉不掉电（由固件决定，是适配前提）？
3. 恢复约束：s2disk时硬件是boot kernel重新编程过的，只能全量重写，不能
   增量恢复。

对应关系的大方向：

| 硬件属性 | 首选机制 | 典型模块 |
|---------|---------|---------|
| 外设 | dev_pm_ops | mmc/i2c/usb/网卡 |
| 外设供电的电源域 | genpd | 平台电源域 |
| per-CPU寄存器 | cpu_pm + cpuhp | GIC CPU interface/timer/MPAM寄存器 |
| 全局唯一寄存器组 | syscore | ITS/时间子系统 |
| 平台低功耗态 | platform suspend_ops | PSCI SYSTEM_SUSPEND |
| 中断线 | IRQ flags四件套 | 唤醒源/关键IRQ |

## 二、回调机制全景

7.2-rc4中与休眠唤醒相关的机制清单，按挂起时触发先后排列：

| 机制 | 注册接口 | 触发位置 | 执行环境 | 适用对象 |
|------|---------|---------|---------|---------|
| 进程冻结 | 框架自动 | DPM之前 | 进程上下文 | 用户进程/freezable kthread，纯软件 |
| pm notifier | register_pm_notifier() | PREPARE/POST_SUSPEND | 原子通知链 | 系统级通知，全树83处，如cpufreq |
| dev_pm_ops | 驱动probe挂到device | prepare/suspend/late/noirq | 可睡眠到关中断 | 外设，main.c:1648-1655 |
| genpd | dev_pm_domain_attach() | 与DPM同阶段 | 同上 | 电源域，pmdomain/core.c:1772 |
| IRQ核心 | suspend_device_irqs() | dpm_suspend_noirq内 | 关中断 | 全部IRQ线，kernel/irq/pm.c:126 |
| cpuhp | cpuhp_setup_state*() | freeze_secondary_cpus | 每CPU | 非启动CPU上的组件，cpu.c:1886 |
| syscore | register_syscore() | 关中断后enter前 | 单CPU关中断 | 全局核心组件，syscore.c:21 |
| cpu_pm | cpu_pm_register_notifier() | syscore内/idle路径 | 单CPU关中断 | 启动CPU的per-CPU寄存器 |
| suspend_ops | suspend_set_ops() | syscore之后 | 关中断 | 平台固件，psci.c:592 |
| cpu_suspend | 架构API | enter最末 | 关中断 | EL1上下文，suspend.c:97 |

其中几个机制的细节：

1. DPM的noirq阶段是IRQ相关的分水岭：dpm_suspend_noirq()内部先
   device_wakeup_arm_wake_irqs()武装唤醒IRQ(main.c:1652)，再
   suspend_device_irqs()停掉其余IRQ(1653)，然后才执行noirq回调(1655)。
   设备自身的dev_pm_ops只负责硬件状态，中断线由IRQ核心统一管理。

2. syscore是"最后停、最先启"的全局组件层：单CPU、关中断、不可睡眠。
   注册序即依赖序：挂起逆注册序执行(syscore.c:47)，唤醒正注册序执行
   (syscore.c:93)。因此依赖方要先注册，唤醒时才先恢复。

3. cpu_pm是syscore里最内层的一条raw通知链(7.2起CPU_PM与CPU_CLUSTER_PM
   事件合并到同一条链，cpu_pm.h:42-57)，挂起时最后触发、唤醒时最先触发。
   它同时被cpuidle调用(cpuidle-psci.c:223)，因此s2idle/s2mem/s2disk共用
   同一套per-CPU保存恢复代码。框架细节见第三节。

4. cpuhp与cpu_pm是"两条腿"：s2mem/s2disk时非启动CPU走cpuhp下线(尾部经
   cpu_die发PSCI CPU_OFF，arch/arm64/kernel/psci.c:68)，启动CPU走syscore
   里的cpu_pm；s2idle时所有CPU都走cpuidle内嵌的cpu_pm。per-CPU组件要两
   个都挂才能全覆盖。

5. cpuhp的注册接口是cpuhp_setup_state()系列(cpuhotplug.h:270起，底层
   __cpuhp_setup_state:250)，状态机对接关系如下：

```c
int __cpuhp_setup_state(enum cpuhp_state state, const char *name,
                        bool invoke,
                        int (*startup)(unsigned int cpu),
                        int (*teardown)(unsigned int cpu),
                        bool multi_instance);
```

| 接口 | 区别 |
|------|------|
| cpuhp_setup_state() | 注册后立即在所有已在线CPU上调startup |
| cpuhp_setup_state_nocalls() | 只注册不立即调用，boot路径已手动初始化 |
| cpuhp_setup_state_multi() + cpuhp_state_add_instance() | 多实例动态状态，teardown按注册反序 |
| cpuhp_setup_state_cpuslocked() | 调用者已持cpus_read_lock |

状态槽分静态槽(enum cpuhp_state预定义，如CPUHP_AP_ARM_ARCH_TIMER_
STARTING)与动态槽(CPUHP_AP_ONLINE_DYN/CPUHP_BP_PREPARE_DYN现场分配)。


## 三、cpu_pm框架详解

### 1. 定位

CPU进深睡/掉电时，挂在CPU上的硬件块(GIC CPU interface、arch timer控制
寄存器、PMU、MPAM CPU寄存器、EL2 hyp、FP状态)的寄存器可能复位，但CPU的
软件身份不变(不下线)。这些块需要知道"CPU要睡了"(保存)和"CPU醒了"(恢复)，
且通知发生在idle/单CPU关中断环境。cpu_pm就是为此造的最小通知框架。

### 2. 数据结构与事件

```c
// kernel/cpu_pm.c:21-26
static struct {
	struct raw_notifier_head chain;
	raw_spinlock_t lock;
} cpu_pm_notifier = {
	.chain = RAW_NOTIFIER_INIT(cpu_pm_notifier.chain),
	.lock  = __RAW_SPIN_LOCK_UNLOCKED(cpu_pm_notifier.lock),
};

// include/linux/cpu_pm.h:40-57
enum cpu_pm_event {
	CPU_PM_ENTER,             /* 单CPU进低功耗态 */
	CPU_PM_ENTER_FAILED,      /* 进态失败，undo用 */
	CPU_PM_EXIT,              /* 单CPU出低功耗态 */
	CPU_CLUSTER_PM_ENTER,     /* CPU电源域(簇)进低功耗态 */
	CPU_CLUSTER_PM_ENTER_FAILED,
	CPU_CLUSTER_PM_EXIT,      /* CPU电源域出低功耗态 */
};
```

7.2把老内核两条链合并为一条，靠事件枚举区分。用raw spinlock的原因
(cpu_pm.c:15-19注释)：通知由idle任务自身发出，永远不能阻塞；PREEMPT_RT
下普通spinlock会睡眠，必须raw系。

### 3. 注册接口

```c
// kernel/cpu_pm.c:61
int cpu_pm_register_notifier(struct notifier_block *nb);
```

按nb->priority插入链(默认0，同优先级追加到链尾)，注册序即通知序。注册
加链锁，遍历靠rcu_read_lock。

### 4. 分发器：两种语义

简单分发cpu_pm_notify(cpu_pm.c:29)，EXIT方向：

```c
static int cpu_pm_notify(enum cpu_pm_event event)
{
	rcu_read_lock();
	ret = raw_notifier_call_chain(&cpu_pm_notifier.chain, event, NULL);
	rcu_read_unlock();
	return notifier_to_errno(ret);
}
```

robust分发cpu_pm_notify_robust(cpu_pm.c:40)，ENTER方向，持链锁：

```c
// kernel/notifier.c:114
static int notifier_call_chain_robust(struct notifier_block **nl,
		unsigned long val_up, unsigned long val_down, void *v)
{
	int ret, nr = 0;

	ret = notifier_call_chain(nl, val_up, v, -1, &nr);   // 正扫计数
	if (ret & NOTIFY_STOP_MASK)
		notifier_call_chain(nl, val_down, v, nr-1, NULL); // 回放前nr-1个
	return ret;
}
```

```
正向:  GIC存 -> timer存 -> arm_pmu存 -> [第4个返回NOTIFY_BAD/STOP]
回滚:  GIC <- timer <- arm_pmu  补发ENTER_FAILED(第4个自己排除)
返回:  错误 -> 调用者放弃进低功耗态
```

### 5. 四个入口与cluster契约

```c
cpu_pm_enter()          // cpu_pm.c:108  robust(ENTER, ENTER_FAILED)
cpu_pm_exit()           // :126  notify(EXIT)
cpu_cluster_pm_enter()  // :147  robust(CLUSTER_ENTER, CLUSTER_ENTER_FAILED)
cpu_cluster_pm_exit()   // :169  notify(CLUSTER_EXIT)
```

cluster事件的调用契约(cpu_pm.c:135-140注释)：必须在域内所有CPU都调过
cpu_pm_enter之后、任一CPU调cpu_pm_exit之前发出。顺序语义：

```
挂起:  [每CPU] enter ... [域] cluster_enter ... 掉电
唤醒:  [域] cluster_exit ... [每CPU] exit
```

域级恢复先于CPU级恢复：共享块先把硬件拉起，各CPU才能恢复自己的寄存器。

### 6. 调用链

cpu_pm_enter/exit只被两个分发器调用，mainline arm64上没有直调：

**链A：syscore路径(s2mem/s2disk，启动CPU)**

```
挂起: suspend_enter(suspend.c:419) -> syscore_suspend(suspend.c:462)
        \-> list_for_each_entry_reverse(syscore.c:63)
              \-> cpu_pm_suspend()             // cpu_pm.c:176
                    +-> cpu_pm_enter()         // :108
                    \-> cpu_cluster_pm_enter() // :147
唤醒: syscore_resume() -> cpu_pm_resume()      // cpu_pm.c:188
        +-> cpu_cluster_pm_exit()              // :169
        \-> cpu_pm_exit()                      // :126
```

syscore_suspend的另外4个调用点(hibernate.c:346/511/630、
kexec_core.c:1185)走同一条内部链。

**链B：cpuidle路径(s2idle/深idle，每CPU)**

```
do_idle(idle.c:278) -> cpuidle_idle_call(idle.c:181)
    \-> cpuidle_enter -> cpuidle_enter_state(cpuidle.c:217/389)
          \-> state->enter() = psci_enter_idle_state(cpuidle-psci.c:218)
                \-> CPU_PM_CPU_IDLE_ENTER_PARAM_RCU(cpuidle.h:311)
                      +-> cpu_pm_enter()       // 进态前
                      +-> psci_cpu_suspend_enter -> cpu_suspend
                      |     \-> PSCI CPU_SUSPEND
                      \-> cpu_pm_exit()        // 唤醒后(enter失败则robust
                                               // 已回滚, 不调exit)
```

s2idle借道此链：s2idle_loop(suspend.c:133) -> s2idle_enter ->
wake_up_all_idle_cpus，各CPU被赶回do_idle后自然走cpuidle路径。

链C(历史)：arm32平台idle代码直调(mach-highbank/pm.c:29、
mach-exynos/pm.c:157、mach-mvebu/pm.c:172等)，这是cpu_pm最初的设计场景，
arm64上已标准化到链A/链B。

两条链的事件不对称：链A发CPU_PM+CPU_CLUSTER_PM两组事件，链B只发
CPU_PM——mainline arm64的cluster事件在cpuidle路径不发，簇域管理走
genpd(OSI拓扑)。

### 7. 驱动侧模板

```c
// 以GIC为例, irq-gic-v3.c:1482
static int gic_cpu_pm_notifier(struct notifier_block *self,
			       unsigned long cmd, void *v)
{
	if (cmd == CPU_PM_EXIT || cmd == CPU_PM_ENTER_FAILED) {
		gic_enable_redist(true);
		gic_cpu_sys_reg_enable();
		gic_cpu_sys_reg_init();
	} else if (cmd == CPU_PM_ENTER) {
		gic_write_grpen1(0);
		gic_enable_redist(false);
	}
	return NOTIFY_OK;
}
// :1503 cpu_pm_register_notifier(&gic_cpu_pm_notifier_block);
```

规则：回调签名统一(nb, cmd, data)，data恒NULL，驱动用per-cpu变量自管
上下文；EXIT与ENTER_FAILED合并处理(都是恢复)；返回NOTIFY_OK(已处理)/
NOTIFY_DONE(不关心)；回调内关中断、不可睡眠、纯寄存器+内存操作。

arm64 7.2挂接者清单：

| 驱动 | 注册点 | ENTER动作 | EXIT动作 |

| GICv3 | irq-gic-v3.c:1503 | grpen1=0、GICR睡 | 唤醒GICR+重写ICC_* |
| arch timer | arm_arch_timer.c:995 | 存CNTKCTL | 恢复CNTKCTL |
| arm_pmu | arm_pmu.c:821 | stop+save | restore+start |
| MPAM | mpam.c:58 | 无 | 重写MPAM0/1_EL1 |
| KVM hyp | kvm/arm.c:2366 | cpu_hyp_reset | cpu_hyp_reinit |
| fpsimd | fpsimd.c:2073 | save_and_flush | 无 |
| SDEI | arm_sdei.c:995 | - | - |

### 8. 与其他机制的分工边界

| 机制 | 关系 |
|------|------|
| cpuhp | CPU下线的组件走cpuhp，CPU不关机只掉电的走cpu_pm，"两条腿" |
| syscore | cpu_pm是syscore链上的一个条目(core_initcall注册)，被cpuidle复用后获得双重身份 |
| dev_pm_ops | 无代码联系，纯顺序契约(DPM在前、cpu_pm在后) |
| genpd/OSI | 簇级共享电源域经genpd管理(dev_pm_genpd_*)，cluster事件主线无arm64用户 |

### 9. 7.2演进点

1. 两条链(cpu_pm/cpu_cluster)合并为一条，事件枚举区分
2. ENTER方向统一robust化(cluster_enter同样robust)
3. PREEMPT_RT下raw化(idle任务不可阻塞约束)
4. cpuidle宏引入is_retention/is_rcu参数，retention态可完全跳过通知

```
          |     \-> its_save_disable()            // irq-gic-v3-its.c:4992
          \-> suspend_ops->enter()                // suspend.c:468
                \-> psci_system_suspend_enter()   // psci.c:540
                      \-> cpu_suspend(0, psci_system_suspend)
                            \-> PSCI SYSTEM_SUSPEND -> 固件断电
```

syscore内部顺序(注册时机决定)：

```
注册序:  ITS(init_IRQ) -> printk(early_initcall)
         -> cpu_pm(core_initcall)
         -> timekeeping/sched_clock/irq_pm/ledtrig(device_initcall)
         -> psci_idle/fw/平台设备probe(设备阶段) -> kvm(运行时)

挂起(逆注册序):  kvm -> 设备阶段组 -> device_initcall组 -> cpu_pm
                 -> printk -> ITS
唤醒(正注册序):  ITS -> printk -> cpu_pm -> device_initcall组
                 -> 设备阶段组 -> kvm
```

即：ITS最后停最先启(保住MSI投递到最后一刻)，cpu_pm次之(CPU interface
最后关)，时间子系统在两者之间。各成员注册点：ITS irq-gic-v3-its.c:5867、
printk printk.c:3849(early_initcall)、cpu_pm cpu_pm.c:205(core_initcall)、
timekeeping timekeeping.c:2323、sched_clock sched_clock.c:329、irq_pm
irq/pm.c:233、kvm kvm_main.c:5702(运行时)。

## 七、寄存器保存与恢复总表

### 1. 核心认知：内存是本源，寄存器是缓存

大部分寄存器根本不"保存"——它们被丢弃，唤醒时从内存里的软件状态重新
计算、重新编程。挂起流程的价值不是"把寄存器抄进内存"，而是"确保内存里
的本源完整"(冻结任务、迁移状态、停设备)，然后放心地把寄存器全部丢掉。

| 类别 | 含义 | 例子 |
|------|------|------|
| 显式保存 | 寄存器->内存，全系统只有4处 | CNTKCTL->saved_cntkctl |
| 重建 | 本源一直在内存，唤醒时内存->寄存器 | CVAL重算、ICC_*重写 |
| 重写默认值 | 确定配置非运行数据，按公式重算 | ICC_*、GICR |
| 缺口 | 无内存副本、无保存、无恢复，靠固件保电 | GICD/mbigen/SMMU |

### 2. 总表：各模块寄存器保存在哪里、怎么恢复

| 模块的寄存器 | 保存到哪里 | 恢复动作 |
|-------------|-----------|---------|
| CPU通用寄存器/EL1系统寄存器 | cpu_suspend保存到内存栈(挂起最后时刻) | cpu_resume入口从栈恢复 |
| 进程的通用寄存器 | task_struct(每次上下文切换都在写) | 进程调度时重新加载 |
| FP/SVE/SME寄存器 | task_struct(惰性:切走时刷回)+启动CPU由fpsimd cpu_pm显式flush | 进程调度时重新加载 |
| arch timer CNTKCTL_EL1 | 显式保存:per-CPU变量saved_cntkctl(arm_arch_timer.c:973) | cpu_pm EXIT写回 |
| arch timer CNTP_CTL/CVAL/TVAL | 不保存 | set_next_event重算CVAL=当前counter+delta(:631) |
| arch timer counter(CNTPCT) | 硬件自身(固件保活) | NONSTOP判定,停了则timekeeping重同步 |
| GIC CPU interface ICC_* | 不保存(确定配置) | gic_cpu_sys_reg_init重写默认值(irq-gic-v3.c:1153) |
| GICR(per-CPU部分) | 不保存 | cpuhp online时gic_cpu_init全量重编程(:1274) |
| GICD | 不保存——缺口 | 假设固件保电 |
| ITS寄存器(CTLR/CBASER) | 显式保存:its->ctlr_save/cbaser_save字段(irq-gic-v3-its.c:4992) | its_restore_enable写回+重同步CMD队列 |
| ITS设备表/中断翻译表 | 本来就在DDR | s2mem保留/s2disk随镜像 |
| mbigen VEC/TYPE | 不保存——缺口 | 假设固件保电 |
| SMMU寄存器 | 不保存——缺口 | 假设固件保电 |
| SMMU STE/CD表 | 本来就在DDR | s2mem保留/s2disk随镜像 |
| CPU PMU配置 | 显式保存:arm_pmu结构体字段(arm_pmu.c:800-830) | cpu_pm EXIT restore+start |
| Uncore PMU计数器 | 不保存(统计量,丢了接受) | 事件迁移,计数丢失 |
| MPAM CPU侧寄存器 | 显式保存:per-CPU缓存arm64_mpam_current(每次线程切换维护) | cpu_pm EXIT写回 |
| MPAM MSC寄存器 | 内存里的resctrl配置结构 | mpam_reprogram_msc全量重编程 |
| KVM EL2状态 | 不保存 | cpu_hyp_reinit从内核代码重建EL2 |
| guest vCPU寄存器 | kvm_vcpu struct(每次vcpu_put写回) | vcpu load时写回硬件 |
| 中断线状态(使能/亲和/挂起) | irq_desc(每次irq操作都在写) | suspend_device_irqs标记/resume恢复 |

### 3. 显式保存只有四处

1. cpu_suspend(): 保存callee-saved+EL1寄存器到内存栈
2. cpu_pm各notifier的ENTER: CNTKCTL->saved_cntkctl、PMU配置->arm_pmu结构
3. its_save_disable(): GITS_CTLR/CBASER读进its结构体字段
4. fpsimd_save_and_flush: 启动CPU的FP状态刷回task_struct

### 4. CPU三种命运：原地睡醒与死亡重生

寄存器保存的前提是"原地醒"：CPU醒来后同一个软件上下文继续跑，才需要
把睡前的状态还给它。判定标准只有一个——醒来后是不是同一个软件上下文。

| CPU命运 | 结局 | 需要保存寄存器吗 | 机制 |
|---------|------|----------------|------|
| 启动CPU(s2mem) | 原地睡原地醒 | 需要 | cpu_pm(有内存副本的不存)+cpu_suspend |
| 每CPU(s2idle/深idle) | 原地睡原地醒 | 需要 | cpuidle路径cpu_pm+cpu_suspend |
| 非启动CPU(s2mem) | 下线->CPU_OFF死亡->CPU_ON重生 | 不需要 | cpuhp teardown+online |

非启动CPU死亡前，teardown把一切有价值的搬进内存：

```
sched_cpu_deactivate -> 任务迁走(最后一次切换把通用寄存器+FP刷回task_struct)
hrtimers_cpu_dying   -> 定时器迁走(hrtimer base是内存)
DSU teardown         -> perf事件迁走(perf_event是内存)
kvm_offline_cpu      -> EL2卸载(guest状态在kvm_vcpu内存里)
arch_timer_dying_cpu -> clockevent关停(next event在tick_sched内存里)
gic teardown=NULL    -> 不拆,掉电自然复位(irq状态在irq_desc内存里)
```

到CPU_OFF那一刻跑在CPU上的只剩idle任务，寄存器没有状态可言。唤醒是
全新boot(secondary_entry -> secondary_start_kernel -> cpu_startup_entry
-> do_idle)，沿cpuhp_up_callbacks从内存重建：gic_starting_cpu重编程
GICR/ICC_*、arch_timer_starting_cpu重新setup、kvm_online_cpu重建EL2、
mpam_cpu_online重编程MSC；调度器分来任务时从task_struct加载寄存器。

cpu_suspend是通用per-CPU设施：s2idle/深idle时每个CPU都经cpuidle调它
(保存自身上下文到自己的栈)；s2mem里只有启动CPU调它，单纯因为其他CPU
已先下线，不是设计上只支持一个CPU。

## 八、各模块挂接细述

### 1. CPU core

启动CPU不能经cpuhp下线(它要执行挂起代码本身)，所以它的上下文保存放到最
后一刻：suspend_ops->enter()里cpu_suspend()经__cpu_suspend_enter保存
callee-saved寄存器和EL1系统寄存器，唤醒从cpu_resume物理入口恢复。非启动
CPU无此限制，直接cpuhp下线+PSCI CPU_OFF。s2disk的CPU上下文走
swsusp_arch_suspend/resume(hibernate.c:333/405)，多出dcache清到PoC和MTE
标签随镜像保存。FPSIMD/SVE/SME寄存器在7.2有独立处理：cpu_pm ENTER时
fpsimd_save_and_flush_cpu_state()把当前CPU的SVE/SME状态刷回task_struct
(fpsimd.c:2073)，唤醒后由进程切换自然恢复。

### 2. arch timer

分三层挂在三处：

| 层次 | 机制 | 内容 |
|------|------|------|
| CNTKCTL_EL1 | cpu_pm:995 + cpuhp online | 唯一显式保存恢复的寄存器 |
| clockevent设备 | cpuhp:1063 + tick syscore | 关停与重编程 |
| 全局时间子系统 | timekeeping syscore:2323 | tick/clocksource/clockevents suspend |
| sched_clock | sched_clock syscore:329 | resume重设epoch防回绕 |

关键结论：CNTP_CVAL/CNTP_TVAL不保存。挂起时arch_timer_shutdown
(arm_arch_timer.c:594)只清CNTP_CTL.ENABLE，比较器里的值直接丢弃，因为
每次编程都重新计算CVAL=当前counter+delta(set_next_event，:631)，从不读
旧值。需要保存的不是寄存器值，而是"下一个事件何时到"这个语义状态，它
在软件内存里三处：

| 语义状态 | 位置 | 存活方式 |
|---------|------|---------|
| 下一个tick时间 | tick_sched->next_tick/next_timer(tick-sched.c:822) | per-CPU内存，s2mem留RAM/s2disk随镜像 |
| 到期定时器 | hrtimer base | 非启动CPU的在cpuhp teardown时迁移到启动CPU |
| 设备状态机 | clockevent_devices链表 | CLOCK_EVT_STATE_*软件状态 |

唤醒重编程链：timekeeping_resume -> tick_resume(tick-common.c:499) ->
tick_resume_local(:455) -> tick_resume_oneshot -> set_next_event重算CVAL
-> hrtimers_resume_local()重排hrtimer。非启动CPU走cpuhp online：
arch_timer_starting_cpu(:827)重新setup+enable PPI。

arch timer的clockevent没有.suspend/.resume回调，clockevents_suspend
遍历时跳过它——不需要，counter自由运行，比较器停掉即可。唯一的显式保
存是CNTKCTL_EL1(per-CPU saved_cntkctl，arch_timer_cpu_pm_notify，:973)，
因为它是EL0访问控制寄存器，软件侧没有镜像；非启动CPU的CNTKCTL由
starting_cpu里的arch_counter_set_user_access()重设。

counter本身是系统外资源：是否保活由固件保证并通过GTDT声明，
arch_counter_suspend_stop决定CLOCK_SOURCE_SUSPEND_NONSTOP
(arm_arch_timer.c:940)，counter会停的平台唤醒后走clocksource重同步。
定时唤醒走RTC alarm，是普通DPM设备。

### 3. GICv3/v4

按硬件块拆开看，各块机制不同：

| 块 | 机制 | 说明 |
|----|------|------|
| CPU interface(ICC_*) | cpu_pm:1503 | ENTER关GRPEN1+redist off，EXIT enable+init |
| Redistributor(GICR) | cpu_pm + cpuhp:1416 | 非启动CPU靠online时gic_starting_cpu重编程(teardown为NULL) |
| Distributor(GICD) | 无 | 主线假设固件保电，掉电场景是缺口 |
| ITS | syscore:5867 | its_save_disable保存CTLR/CBASER后quiesce禁用，restore全量重编程 |
| SPI mask | IRQ核心 | suspend_device_irqs + MASK_ON_SUSPEND(1525/1544)不在GICD逐条mask |

注意GICv5新驱动(irq-gic-v5.c)目前只有cpuhp(1021)，无cpu_pm/syscore，
深睡场景未闭环。

### 4. mbigen

mbigen是wired-to-MSI转换器，mask/unmask委托parent(ITS)，自身VEC/TYPE寄
存器无任何PM机制。ITS侧已由its_save_disable/restore_enable闭环(device
table在DDR，s2mem保留/s2disk随镜像)，但mbigen寄存器掉电后event ID和触发
类型全丢。补法是per-pin缓存+register_syscore全量重写VEC/TYPE。注册时机
天然正确：probe阶段注册晚于ITS，唤醒时ITS先恢复、mbigen后重写。

### 5. SMMUv3

主线无任何PM回调。SMMU是DMA设备的服务提供者，正确机制是dev_pm_ops：
iommu core在attach时创建stateless device link(iommu.c:518)，SMMU挂了PM
回调后自动晚于DMA客户端挂起、早于它们恢复。suspend侧排空CMDQ并禁用，
resume侧必须全量重编程(复用probe路径)，因为s2disk时硬件是boot kernel
配置的，增量恢复不可行。

### 6. PMU

CPU PMU(arm_pmu)是per-CPU资源，cpu_pm ENTER时stop+保存计数器配置、EXIT
恢复+start(arm_pmu.c:821)，已闭环。Uncore PMU(DSU/CMN)的cpuhp回调只是
perf事件亲和迁移(arm_dsu_pmu.c:846、arm-cmn.c:2682)，不保存恢复硬件寄存
器，计数域掉电后counter配置丢失，需要补dev_pm_ops或syscore。

### 7. MPAM

两半各挂一路：CPU侧MPAM0/1_EL1、MPAMSM_EL1走cpu_pm(arch/arm64/kernel/
mpam.c:58)，EXIT时从per-cpu缓存重写；MSC侧走cpuhp引用计数状态机
(mpam_devices.c:1932)，最后一个可达CPU下线时把MSC写回reset态，第一个
CPU上线时reprogram。缺口在启动CPU：它不走cpuhp，其可达MSC若随挂起掉电
则无人恢复，补法是把reset/reprogram挂到CPU_CLUSTER_PM事件或注册晚于
cpu_pm的syscore(唤醒时先恢复MSC再恢复MPAM0/1_EL1)。

### 8. 虚拟化(KVM)

KVM每CPU状态挂在三条路上：

| 路径 | 机制 | 动作 |
|------|------|------|
| 非启动CPU | cpuhp CPUHP_AP_KVM_ONLINE | kvm_offline/online_cpu |
| 启动CPU EL2向量 | cpu_pm hyp notifier arm.c:2366 | ENTER cpu_hyp_reset/EXIT cpu_hyp_reinit |
| 启动CPU全套EL2 | generic kvm syscore kvm_main.c:5702 | kvm_suspend/kvm_resume |

generic kvm syscore是7.2新增的：kvm_suspend调kvm_arch_disable_virtual-
ization_cpu(arm.c:2316)，包含kvm_timer_cpu_down/kvm_vgic_cpu_down/
cpu_hyp_uninit。guest全部状态在内存里(vcpu寄存器、vGIC、stage-2页表、
vtimer)，随s2mem/s2disk天然保存，恢复后guest仅感知时间跳变。pKVM例外：
notifier明确跳过(arm.c:2363)，hyp上下文不在内核镜像里，s2disk基本不可行。

## 九、机制选择规律

新增硬件模块或补缺口时按以下顺序决策：

1. 先问固件：该模块挂起时所在电源域掉不掉电？不掉电则什么都不用做。
2. 掉电的话，寄存器是per-CPU的还是全局一份的？
3. 恢复时能否增量？s2disk一律只能全量重写。

| 场景 | 机制 | 理由 |
|------|------|------|
| 外设 | dev_pm_ops | 可睡眠、device link自动排序、支持wake irq |
| 外设电源域 | genpd | 域级开关，dev_pm_genpd_suspend |
| per-CPU寄存器 | cpu_pm + cpuhp双挂 | s2idle走cpuidle的cpu_pm，s2mem非启动CPU走cpuhp |
| 全局寄存器且要最后停最先启 | syscore | 单CPU关中断环境，注册序即依赖序 |
| 平台低功耗态/唤醒源 | suspend_ops/固件 | 内核只发一次enter |
| 中断线 | IRQ flags | NO_SUSPEND/EARLY_RESUME/wake irq/MASK_ON_SUSPEND四件套 |

syscore注册时机决定依赖顺序，典型锚点：

| 目标顺序 | 注册时机 |
|---------|---------|
| 比cpu_pm早恢复(如GICD、MSC cluster) | init_IRQ阶段或早于core_initcall |
| 比cpu_pm晚恢复(如ITS依赖方mbigen) | probe阶段即可 |
| 最后停最先启(保住投递到最后) | init_IRQ阶段(ITS的现状) |

中断线四件套的语义：IRQF_NO_SUSPEND豁免suspend_device_irqs；
IRQF_EARLY_RESUME在syscore resume阶段先恢复(irq_pm_syscore，irq/pm.c:233)；
dev_pm_set_wake_irq武装唤醒IRQ(全树65处)；IRQCHIP_MASK_ON_SUSPEND让IRQ核心
走chip mask而不是逐条软屏蔽(GIC靠关CPU interface阻断投递)。

## 十、注意事项

1. 7.2 API演进：register_syscore_ops改为register_syscore(struct syscore)
   (syscore_ops.h:13-24)；cpu_pm两条链合并为一条，CPU_PM与CPU_CLUSTER_PM
   用事件枚举区分(cpu_pm.h:42-57)；genpd移到drivers/pmdomain/core.c。
2. 新增IRQF_EARLY_RESUME + irq_pm_syscore(irq/pm.c:233)：syscore resume
   阶段先恢复这批线，resume_device_irqs(246)只恢复其余。
3. 新增psci_idle_syscore(cpuidle-psci.c:203)和CPUHP_AP_CPU_PM_STARTING
   (cpuidle-psci.c:217)：PSCI OSI层级拓扑下CPU挂到genpd域，s2idle/s2ram
   经dev_pm_genpd_suspend/pmdomain/core.c:1772管理CPU电源域。
4. 新增generic kvm syscore(kvm_main.c:5702)：与hyp cpu_pm notifier叠加，
   挂起时kvm_suspend先跑(注册最晚)，随后cpu_pm_enter再走cpu_hyp_reset。
5. 对旧文档的修正：ARM64休眠唤醒组件适配分析中GICD syscore"注册晚于
   cpu_pm"的表述与正序resume矛盾。syscore唤醒是正注册序执行，GICD要在
   CPU interface(cpu_pm)之前恢复，必须注册早于core_initcall，即与ITS
   同批放在init_IRQ阶段。
6. s2disk的恢复语义：syscore_resume发生在swsusp_arch_resume跳转之后的
   镜像内核里(hibernate.c:373)，用镜像内存状态恢复，因此所有恢复回调都
   必须是全量重写型，不能依赖"寄存器当前值"。
7. GICv5驱动(irq-gic-v5.c)无cpu_pm/syscore，只有cpuhp(1021)，在其平台
   上做深睡前需补。
8. s2idle与s2mem的分水岭在suspend_enter：s2idle走s2idle_loop(suspend.c:
   449)经cpuidle逐CPU进深睡，不触发cpuhp/syscore/platform enter，所以
   s2idle只覆盖挂了cpu_pm的per-CPU组件；全局组件(ITS/SMMU/MSC)在s2idle
   下依赖其电源域不掉电的假设。
